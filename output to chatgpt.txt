5. UX / Pedagogy Changes (short)
- **LEARN:** One screen per "card" / block type where possible; bilingual section labels; micro-check can show a short prediction step before listed options (if enabled).
- **Lesson pedagogy:** Server-side Markdown is split into ordered pedagogical blocks; **examples lead** when lesson Markdown follows the H2 template.
- **Feedback:** Wrong answers aim for **why the choice looked plausible** + **decisive difference** + **one-sentence rule**, not only "correct is B".
- **Warm-up:** Short activation quiz before main flow; does not replace FSRS review or topic test.
- **Hesitation:** Surfaces "fluent vs hesitant vs struggling" style tiers for reflection and downstream selection hints—not a second grading system.
- **Revisit:** After weak signals, practice may insert **delayed** extra items (variants first); capped per session; overflow goes to next-practice reinforce queue.
- **Prediction:** Optional think-first step before four options on eligible early practice items and some micro-checks.
- **Listening workbook:** User opens **YouTube (etc.) in a new tab**; same page holds rounds, transcript (default collapsed), dictation/shadowing, takeaway, tomorrow review points.

- **Automated tests:** No full `npm test` suite was required for this closeout; repository has some unit tests (e.g. hesitation, choice-feedback) where present.

- **Prediction / revisit** use heuristics; edge cases (thin question pools, very short stems) may skip features or defer to queue.
- **Listening workbook** content is **authoring-driven**; demo seed is illustrative; transcript quality depends on DB content.
- **Multi-user / auth:** still dev-user oriented; progress isolation is not a product-grade multi-tenant guarantee.
- **Local working tree:** If any teammate had **uncommitted** experiments, resolve before relying on this handoff—prefer pulling the tagged closeout commits.
